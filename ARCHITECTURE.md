# Проектное решение — этап 1
Дата выполнения: 24.11.2026. Продвинутый уровень, N=21, k=4, ALPHA=3, R=3, NodeID 256 бит, три ретранслятора и три туннеля. N=21 соответствует рекомендованному масштабу ТЗ; невырожденность предстоит проверить на этапе 6. Python 3.12+, asyncio для конкурентного TCP без потока на каждое соединение, struct для заголовка, JSON для читаемости и простоты отладки, logging для диагностики, unittest для тестов без внешних зависимостей. MessagePack используется только в сравнении. JSON и MessagePack поддерживают расширение объектов новыми полями; оба требуют отдельной проверки схемы, JSON удобнее для ручного просмотра, MessagePack компактнее. Измерения в results/benchmark.json подтверждают разницу для выбранных текстовых объектов, но не универсальное преимущество.

Слои: main — CLI; config — настройки; node — обработка RPC; transport — TCP, тайм-ауты, очередь кадров; protocol — заголовок, декодер и JSON. Декодер накапливает максимум 24 байта заголовка, затем проверяет длину и только после этого накапливает тело. Чтения ограничены 4096 байтами; число соединений и кадров на соединение ограничено. Ошибка закрывает только соответствующее соединение. Один исходящий RPC на соединение; входящее соединение может обслуживать несколько последовательных запросов.

Следующие этапы: собственная Kademlia-lite, Ed25519 identity, учебный AKE на cryptography (X25519, HKDF-SHA-256, AES-256-GCM), end-to-end защита, файлы, Docker Compose, star/ring/tree/multi-seed, ограниченный underlay и netem. Сейчас они не реализованы. TCP открыт, не предназначен для секретных данных. Параметры будущих подсистем пока проектные. Утверждение преподавателем и коммит выполняются студентом.

## Анализ аналогов и обоснование выбора (редакция 25.11.2026)

| DHT | Организация | Поиск | Ограничения для стенда |
|---|---|---|---|
| Kademlia | XOR-метрика, k-bucket | Параллельный итеративный поиск ближайших контактов | Нужны refresh, контроль невырожденности и защита от Eclipse |
| Chord | Кольцо идентификаторов, finger table | Переходы к предшественнику/преемнику ключа, O(log N) при стабильном состоянии | Нужны стабилизация кольца и актуальные finger tables |
| Pastry | Префиксная маршрутизация, leaf set | Увеличение общего префикса, типично O(log N) | Более сложное обслуживание таблиц и leaf set |

Выбрана Kademlia: XOR и ограниченные корзины непосредственно соответствуют ТЗ, параллелизм ALPHA=3 позволяет исследовать отказы. Асимптотика не гарантирует выигрыш на 21 узле; это проверяется экспериментально. Анализ качественный, реализации альтернатив не заявляются.

## Сравнение защиты канала (проектное, этап 4)

| Подход | Аутентификация и ключи | Применимость |
|---|---|---|
| TLS 1.3 | Сертификаты или PSK, обычно эфемерный обмен ключами, AEAD | Зрелый стандарт; потребуется привязка удостоверения к NodeID |
| Noise | Шаблоны handshake со статическими/эфемерными ключами, AEAD | Гибкая P2P-аутентификация; требуется проверка доверия к identity |
| Учебный AKE | Ed25519 подписывает транскрипт, X25519, HKDF-SHA-256, AES-256-GCM | Выбран по ТЗ продвинутого уровня; не заменяет проверенный промышленный протокол |

План: свежие эфемерные ключи и session_id, подпись канонического транскрипта с ролями, версиями, NodeID, ключами и случайными значениями; отдельные ключи направлений, уникальные nonce, счётчики и replay-защита. Примитивы только из cryptography. На этапе 1 аутентификации и конфиденциальности нет. Ретрансляторы в будущем не должны видеть прикладной plaintext.
